# 班薪记

面向倒班员工的个人工资记录网页。React 19 + TypeScript + Vite；没有业务后端、注册或上传工资数据的接口。浏览器 localStorage 保存账本，手机和桌面响应式布局。

## 在线使用与 GitHub 部署

电脑或手机浏览器直接打开：**https://mnijc19-netizen.github.io/shift-pay-ledger/**

源码仓库：https://github.com/mnijc19-netizen/shift-pay-ledger

推送 `main` 后，GitHub Actions 自动运行工资计算测试、构建并部署到 GitHub Pages。无需启动本地服务器，也不依赖 ChatGPT 或 Codex 的内置站点。Vite 使用相对资源路径，支持仓库子目录网址。

网页无需登录。每台设备、每个浏览器独立保存账本；手机与电脑不会自动同步，可在「数据与备份」通过 JSON 迁移。原内置网址与 GitHub Pages 的存储也相互独立，迁移时应导出并恢复 JSON。

## 启动与测试

需要 Node.js 22.12+ 或 Node.js 24 LTS。在本项目目录执行：

```powershell
npm ci
npm run dev
```

打开终端显示的 Local 地址（通常为 `http://localhost:5173`）。也可右键使用 PowerShell 运行 `start.ps1`。电脑和手机在同一网络时，使用终端显示的 Network 地址。需要电脑允许该开发服务通过本机防火墙；网页代码本身不更改防火墙。

```powershell
npm test              # 独立计算函数的单元测试
npm run build         # 严格 TypeScript 检查与生产构建
npm run preview       # 本地预览 dist
npx playwright install chromium
npm run test:e2e      # 浏览器交互及手机布局测试
```

可选浏览器配置：PowerShell 中设置 `$env:PLAYWRIGHT_CHANNEL='msedge'` 使用已安装且允许自动化的 Edge，或设置 `$env:PLAYWRIGHT_EXECUTABLE_PATH` 指向兼容的测试版 Chromium。默认使用 Playwright Chromium。本次验收使用独立 Chromium 测试浏览器，没有更改系统浏览器策略。

## 第一次使用

1. 已内置福州2195元、标准五天八小时、21.75天折算与法定加班规则；「工资规则」默认收起详细参数，可查看依据与差异。
2. 「考勤日历」选择白班或夜班，再点空白日期即可直接录入。白班 08:00、夜班 20:00 开始，默认计薪 12 小时，不扣吃饭时间。提前下班只需填写工时；保存后下次恢复默认 12 小时。再点已有日期，首先查看当日工资明细（工时×单价×倍率、餐补和合计），也可直接改工时；特殊情况用「详细设置」。
3. 「工资总览 → 本周期参数」选择完整或部分周期，填写实际计薪天数、绩效、津贴资格与扣款；有实际依据再打开确认开关。
4. 「工资条核对」逐项录入工资条与实际到账，项目合计不自动当作银行到账。工资条确认不自动追加收入，以免重复计薪。
5. 「保存工资快照」锁定当前规则、考勤和计算明细。「数据与备份」查看快照、修改记录、导出 CSV 或备份与恢复 JSON。

工资周期月份指结算截止月。选择 **2026-09** 可直接查看历史工资条七项 **¥715.42**；已预存原始历史快照。选择 **2026-10** 为 2026-09-26 至 2026-10-25。

界面默认深色，右上角可切换浅色，主题偏好会在此浏览器保留。快速录入会记住白班 / 夜班选择，工资条确认过的历史工时与快照不会因为新默认值而改变。

日历显示每日**税前预计收入**：正常计薪工时按21.75天、8小时折算，加上加班费和本班补贴；休息日加班不再额外加一份日基本工资。月度绩效、津贴、礼金和扣款在周期核算，日历展示不会再次加进月基本工资。普通工作日12小时白班约¥176.61，同为工作日的12小时夜班含25元晚餐补贴约¥201.61。按用户指定，整班使用开始上班日期的标准，过零点不换倍率。周末、调休和节假日以开始日判断。

标准工时下按周末休息，官方调休工作日覆盖周末；休息日未补休2倍，法定当天3倍，其他工作日超8小时1.5倍。默认不扣吃饭工时。夜班整班按上班日期使用同一倍率。个人排班变化可关闭日历覆盖或修正分段，已补休不自动计2倍。批量排班仍先生成草稿。

2026年10月起新周期默认使用**福州最低个人缴费参考¥590.80/月**：养老4579×8%=366.32、医保4579×2%=91.58、失业4579×0.5%=22.90、公积金2195×5%按元四舍五入=110。实际扣款逐项覆盖，填0可明确本期未扣；不是企业实际申报的替代。实际基数高于最低时不能一律最低申报。按自然月参考，不按26–25工资周期天数摊薄；补缴、跨月扣款、个税按实际录入。新参加工作首月不预扣公积金，调入等情况按实际覆盖。工伤、生育的单位负担和医保个人账户划扣长护险不重复扣工资现金。2027年沿用最后核验值并提示待更新。

旧账本首次打开自动升级并写修改记录：实际金额、考勤工时及已有历史快照保留；2026年10月以前的旧周期保留原折算分母，并在缺少快照时保存升级前结果。旧JSON恢复也执行同一升级；历史715.42元继续按原23天口径核对。

## 计算约定与数据保护

- Decimal.js 使用 40 位有效数字。金额以十进制字符串存储；小时单价和中间金额不先取整。同类、同确认状态的加班先合并，工资项目最后按人民币分四舍五入或截取，汇总各项目分金额。因此历史七项合计精确为 ¥715.42。
- 月基本工资只生成一笔。工作日按班次开始日期共享一次标准工时额度，同日分多段记录不会重复获得 8 小时正常额度，跨午夜也不重置。休息日已补休不自动按双倍计费。未确定的加班类型不先猜测工资，计薪工时会作为待确认事项提示。
- 周期与默认工资类型均按班次开始日期归属，过午夜不重置8小时额度、不换日期倍率。详细规则仍保留显式开启按实际日期分别计算的选项；手动分段修正优先。新录入默认不扣吃饭或短休息。详细设置仍支持有明确依据的非计薪休息，重叠休息合并，避免重复扣除；吃饭位置可按上班后分钟数指定。已保存的旧考勤维持原工时，快捷录入则始终优先使用用户填写的小时数。
- 手动计薪工时优先，不再减去休息。跨日期默认按原计薪时段比例分配，界面明确提示；可逐段指定工时与类型。逐段小时必须全部填写、和总工时相等且不超出相应时段。
- 未录入日期不推定出勤、缺勤或休息。完整周期基本工资是一项明确标示的预测假设；缺勤扣款须输入依据和实际金额，不从缺勤天数自动推算。
- 用户已确认每月400元充入饭卡，单列为非现金福利，不计应发或实发工资；夜班餐补另计现金。饭卡与逐班现金餐补互不覆盖。其他项目仍按现金、非现金和未知方式分别汇总。
- 绩效基数空白时不自动生成绩效；¥68.25 只用于历史周期。高温与礼金须按周期启用。个税仅录入实际扣款，不在累计预扣资料不足时输出估算。
- 保存规则会增加规则版本。依赖旧规则的确认金额转为预计，需重新核验；已录入的实际金额及历史快照保留。周期编辑和考勤编辑也会保留确认依据对应的规则版本。
- 所有保存、修改、删除与恢复均保留前后值及备注。不可变快照记录保存时的结果；当前预测会随规则变化，历史工资条实际数据不被计算结果覆盖。
- 重复考勤 ID、重叠出勤时段、非法日期与数值、无效 JSON 都会被拒绝。读取损坏本地数据时不覆盖原文，可导出原始内容；存储写入失败会提示，界面不会假装保存成功。
- CSV 使用 UTF-8 BOM，兼容中文 Excel，并转义逗号、引号、换行与公式注入字符。JSON 恢复前导出原账本；恢复采用整体替换，不能作为合并导入。CSV 用于查看，不能恢复完整账本。
- 本地数据按浏览器与网址隔离，不自动跨设备同步。换网址、设备或清理浏览器前请导出 JSON。HTTP 局域网访问与 localhost 也有独立的本地账本。

## 仍需本人确认

| 事项 | 当前处理 |
| --- | --- |
| 个人实际排班 | 按用户指定的标准五天八小时，个人排班有变化可修正 |
| 每周期应计薪、实际计薪天数及日折算分母 | 可逐期设置，默认21.75，历史周期单独保留23 |
| 缺勤扣款依据 | 不自动扣薪，实际金额手动录入 |
| 每月400元餐补 | 已确认是饭卡充值，单列福利；夜班餐补计入工资 |
| 晚餐补贴资格与实际金额 | 两班倒加班超过22点，预计25元/次，实际金额优先 |
| 公司夏季福利与法定高温作业津贴 | 截图6–9月50元是公司项目，不能替代符合条件时260元/月或12元/天的法定津贴 |
| 正式员工绩效标准与折算办法 | 标准留空，只录入本期实际绩效 |
| 国庆礼金、正式员工礼金 | 仅按需求给出默认福利标准，需按期核验 |
| 社保、公积金实际申报与补缴、个税 | 已有最低参考，工资条实际扣款优先覆盖；个税只录实际 |
| 参考钟点、吃饭时间与加班归类 | 逐班修改，支持跨午夜分段修正 |

    seed.ts        已知初始数据和历史工资条
    storage.ts     localStorage、JSON 与 CSV
    engine.test.ts 计算与数据单元测试
  components/
    Overview.tsx   工资总览与逐笔公式
    Attendance.tsx 考勤日历、班次编辑、排班草稿

    CycleEditor.tsx 周期计薪、福利与扣款
    Reconcile.tsx  工资条逐项核对和到账记录
    ui.tsx         通用表单与弹窗

这是浏览器网页小程序，可直接在手机浏览器使用；没有包含微信原生小程序发布包、云同步或自动累计个税估算。


## 夜班归日口径（2026-10-22 用户确认）

整班使用开始上班那一天的标准。例如10月6日20点到次日8点，全部按6日计算；这是用户指定的个人记账口径，不另称为全国统一的跨午夜法律规则。10月6日为国庆调休休息日，默认未补休时整班12小时按2倍，另符合条件的晚餐补贴25元，日历预计327.76元。10月9日、10日开始的12小时夜班均按工作日，预计201.61元；11日开始的按休息日，预计327.76元。

普通工作日时薪基数2195÷21.75÷8=12.61494253…，不会先取整为12.62。正常8小时约100.92、加班4小时约75.69，合计176.61；符合晚餐补贴条件再加25，为201.61。已有11.5小时记录仍为192.15，保留实际录入工时，不自动补成12小时。点开日期后直接显示正常工资、加班费、补贴的分项解释。

旧浏览器账本与旧JSON恢复均自动改用整班归日一次，并记录规则版本与修改记录。已有工时、实际扣款、手动分段修正、工资条、历史快照保留；之后主动更改详细归日设置不会在刷新时被再次覆盖。


## 日明细与当月工资条

日历点开已有日期，先显示「当日工资明细」：正常工时工资、分类型加班费、夜班/白班餐补，以及税前合计。每行直接展示工时、5位小数单价和倍率，内部计算仍保留40位精度；若分项显示取整与总额有1分钱差异，单列取整差额，保证解释合计对得上。休息日不重复增加正常工资，法定日带薪基本工资分摊单列。一天多个班段共享正常工时额度，草稿和未知类型明确区分。

当月工资条将「工资收入·加项」「个人扣款·减项」「饭卡与非现金福利」分开。夜班餐补和同类加班项目按月合并显示，点击仍可追溯原记录。应发工资不含饭卡，预计实发=应发−个人扣款，月基本工资只计算一次。

「记录绩效/其他收入」可录本期实际绩效或自定义现金奖金、礼金、补发。再次录入绩效会替换旧实际绩效，不叠加；其他收入逐笔追加。详细编辑、删除仍使用「本周期参数」。工资条核对支持夜班餐补合计，实际记录按工资加项、扣款、非现金和未分类分别汇总，避免将400元饭卡混入工资金额。

旧浏览器账本和旧JSON恢复会将月餐补从现金/未知更正为饭卡，记录修改前后规则，已有银行到账、手填金额、出勤与历史快照保留。
